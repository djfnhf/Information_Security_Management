# 项目约束文档（AI 协作总约束）

> **使用方式**：每次开启新的 AI 对话时，将本文件**完整粘贴**给 AI 作为首条上下文。
> 目的：解决"AI 遗忘早期约束"问题，使每轮对话都在统一的安全边界内进行。
> 依据：本约束由 [risk-analysis.md](risk-analysis.md) 的风险识别结论转化而来。

---

## 一、背景说明

- 本仓库包含 `漏洞靶场/DVWA/`——一个**故意设计的存在已知漏洞的教学靶场**，以及 `成员代码/` 下的安全学习工具。
- 已识别的高危风险包括：命令注入(RCE)、SQL 注入、任意文件上传(WebShell)、文件包含(LFI/RFI)、反射/存储/DOM 型 XSS、CSRF、弱口令爆破、越权(IDOR)、弱会话、开放重定向、弱加密。
- 当前工作目标：在该靶场基础上进行**防御性安全分析、教学讲解与防护代码编写**。

## 二、任务范围

- ✅ 允许：漏洞成因分析、按安全等级对比讲解、编写/审查防护代码、生成安全文档、对照 `impossible.php` 给出修复。
- ✅ 允许：仅在本地/隔离环境内的演示与验证。
- ❌ 不在范围：攻击真实第三方目标、武器化利用、规避检测、大规模扫描。
- 修改文件前需我确认范围；除非我明确要求，不提交、不推送 git。

## 三、约束条件（必须遵守）

1. **输入不可信**：所有 `$_GET/$_POST/$_REQUEST/$_FILES/$_COOKIE/$_SERVER` 输入一律校验后再用。
2. **参数化查询**：所有 SQL 使用预编译 + 参数绑定，禁止字符串拼接。
3. **输出编码**：所有回显到 HTML 的数据使用 `htmlspecialchars()`（或等价）编码。
4. **命令安全**：避免调用系统命令；必需时用白名单 + `escapeshellarg()`。
5. **文件安全**：上传做扩展名/MIME/内容白名单校验、重命名、目录禁脚本；包含用白名单映射。
6. **鉴权与防护**：敏感操作用 POST + 一次性 CSRF Token；登录有频率限制；口令用 bcrypt/argon2 加盐。
7. **不弱化安全**：保留并启用安全响应头与 CSP，不得关闭已有防护。
8. **可追溯**：分析与修复需引用具体代码位置（文件:行号），并说明风险与依据。

## 四、禁止行为（红线）

- 🚫 禁止生成可直接攻击真实目标的完整 PoC / 武器化 exploit / WebShell 样本。
- 🚫 禁止在代码中引入 `eval`、动态 `include`、未过滤的 `shell_exec/system/exec` 等危险调用。
- 🚫 禁止编写绕过/关闭安全机制的代码（如关闭 XSS 防护、移除 CSRF Token、关闭转义）。
- 🚫 禁止针对真实数据库/主机的拖库、爆破、路径穿越完整利用链。
- 🚫 禁止在未确认的情况下修改指定范围之外的文件，或执行 git 提交/推送/破坏性操作。
- 🚫 禁止将靶场或敏感数据建议暴露到公网。

## 五、出现冲突时

若我的某条请求与上述约束冲突，请**先指出冲突点并暂停**，等待我确认，不要默默执行。
